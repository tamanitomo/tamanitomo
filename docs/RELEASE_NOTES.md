Tamanitomo 3.0.2 is about saying what is wrong while it can still be acted on.

Importing a workflow from a picture is how most people start, and it failed three separate ways, each blaming something other than itself. A render saved by ComfyUI carries a non-finite number on its nodes, which read back perfectly well and then made the reply impossible to encode — the error named no file and pointed nowhere. A graph built with a node pack was read by a reader that knew four stock node names, so it came back with no model, no LoRA, no numbers and no wired prompt, and was called incomplete for being unfamiliar; a pack's sampler still calls its inputs `steps` and `cfg`, and that is what is read now. And a link copied from the civitai.red mirror died at the fetch, because that host refuses an ordinary client, with an error that blamed the link.

The larger change is that an import now says what your ComfyUI is missing. A workflow naming a node pack you do not have, or a model twice the size of your graphics card, used to fail much later with an out-of-memory error thrown from somewhere deep inside ComfyUI — which reads as "this is broken" rather than "install this" or "this will not fit on this card". The import names the missing nodes, names the missing weights, reads the card's VRAM, and where a model will not fit says so plainly and explains that the same weights usually exist quantised, at a size that will. It does not offer that advice to someone who already has a quantisation.

Importing also stopped throwing away the useful part. A workflow from somebody else's picture runs their way, which matches this kit's only by luck — their nodes, their prompt arrangement, none of the contract. What actually transfers is not the wiring but the ingredients: the model, the LoRAs and the strengths they were run at, the sampler settings. Those are now read out and rebuilt into a lane of this kit's own shape, where the prompt sits in its usual boxes and the companion's settings apply as they do everywhere else. You are offered that lane, the graph as detected, and a download of the original file exactly as published — three things from one import, and a plain explanation of which is which.

The architecture is read from the graph's own wiring. A text encoder loaded as `krea2` has said what it is; a file named `krea2_something` has only said what somebody called it, and that distinction is the difference between a lane that works and one that fails at the first render. A graph that declares nothing is not guessed at. Settings recovered from a stranger's image are checked as strictly as typed ones, and a workflow needing nodes your ComfyUI does not have is called what it is rather than reported as ready.

Two smaller things that had been quietly wrong for a while. A character LoRA does nothing until its trigger word appears in the positive prompt, and there was nowhere for that word to live — it is now part of a companion's own quality tags, reaching ComfyUI lanes without displacing the appearance she is described by. And `feeling` had no box in the workflow template, so every lane built from it resolved how she felt on each render and dropped it.
